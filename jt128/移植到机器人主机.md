# 移植到机器人主机

结论：**可以移植，而且已经做成了一套脚本**。我在这台机器上用隔离的假 HOME 完整演练过一遍（含编译两个包），确定能落地。

## 三步走

```bash
# ── 在桌面机（x86）上打包 ──
bash ~/jt128/port/make_bundle.sh ~/          # 产物 ~/jt128_port_YYYYMMDD.tar.gz（约 370 KB）
scp ~/jt128_port_YYYYMMDD.tar.gz <机器人主机>:~/

# ── 在机器人主机上 ──
tar xzf jt128_port_YYYYMMDD.tar.gz
cd jt128_port_YYYYMMDD
bash jt128/port/deps_check.sh                # 先看缺什么
bash jt128/port/port_setup.sh "$PWD"         # 一键部署 + 编译
```

`port_setup.sh` 会自动：环境自检 → 装到 `~/jt128` → 装驱动源码到 `~/HesaiLidar_ROS_2.0` → **改写 config.yaml 里两处硬编码绝对路径** → `colcon build`（驱动 + C++ 中继）→ 往 `~/.zshrc` 追加 source 行（先备份）。

之后在新终端：

```bash
sudo ~/jt128/setup_host.sh <网卡名> 192.168.1.100    # 网卡名自己填，脚本不写死
jt128check                                           # 先证明雷达在发数据
jt128up && jt128verify                               # 接真机导航栈
```

## 绝对路径审计结果

| 位置 | 原状态 | 处理 |
|---|---|---|
| `config/config.yaml` 的 `correction_file_path` / `firetimes_path` | **硬编码 `/home/wzj/...`**（移植头号障碍） | `port_setup.sh` 自动改写成目标机实际路径，并校验文件存在 |
| `jt128.zsh` 里 `source /opt/ros/humble/setup.zsh` | 写死 humble | 改成 `$ROS_DISTRO`，找不到时给出提示 |
| `jt128_verify.sh` 里 `/opt/ros/humble/setup.bash` | 写死 humble | 同上 |
| `jt128.zsh` 里 `enp131s0` | 写死网卡名 | 改成 `$JT128_IFACE`，否则自动找带 `192.168.1.x` 地址的网卡 |
| `setup_host.sh` 调 `ethtool` | 依赖 ethtool | 改成可选（缺失只提示，不报错） |
| `sim/gt_sim_jt128_params.yaml` 的 `yaml_filename` 绝对路径 | 继承自你的原文件 | 仿真专用，**机器人主机用不到**；若要在别处跑仿真需同步改 |
| `jt128_check.py` / `memwatch.py` / `jt128.zsh` 其余部分 | 无绝对路径（用 `$HOME`、`$JT128_DIR`） | 无需处理 |

> 说明：`config.yaml` 里那两处路径是**本地兜底**。真雷达连上时 `use_ptc_connected: true` 会优先通过 PTC（端口 9347）从雷达本身取角度修正文件，兜底文件只在取不到时才用。firetime 反过来：JT128 不会从雷达自动取，**必须**有这个文件（SDK 自带的是通用型号文件，所有 JT128 通用，不是单机标定）。

## 环境依赖清单（`deps_check.sh` 会自动逐项检查）

**必须有**：

| 类别 | 内容 | 安装（以 humble 为例） |
|---|---|---|
| ROS 2 | `/opt/ros/<distro>`（机器人上是什么发行版就用什么，脚本跟随 `ROS_DISTRO`） | 已有 |
| ROS 包（驱动编译） | `ament_cmake ament_index_cpp rclcpp rclcpp_action rcl_interfaces rcutils sensor_msgs std_msgs builtin_interfaces rosidl_default_generators rosidl_typesupport_c` | `apt install ros-$ROS_DISTRO-<包名>` |
| ROS 包（导航/验证） | `nav2_bringup nav2_costmap_2d tf2_ros` + 你的 `cpp_lidar_filter`（在 cod 工作区） | 已有 |
| 三方库 | `libyaml-cpp-dev`、`libboost-thread-dev libboost-system-dev` | `sudo apt install ...` |
| 工具链 | `colcon cmake g++` | `python3-colcon-common-extensions` |
| C++ 中继 | 只要 `rclcpp` + `sensor_msgs` | — |

**可选**：`python3-numpy`（干跑点云脚本）、`tcpdump`（抓包排查）、`nmcli`（持久化网口配置）、`ethtool`（看链路速率）、`rsync`。

**不需要**：CUDA（`FIND_CUDA` 默认关）、libpcap、上位机 LidarUtilities。

## 不能直接拷的东西（重要）

| 东西 | 为什么 |
|---|---|
| `~/hesai_ws/build`、`install` | `install` 里是**软链**（`.../hesai_ros_driver_node -> /home/wzj/hesai_ws/build/...`），换机器必断；`CMakeCache.txt` 里嵌了 11 处本机绝对路径。**必须在新机器重新编译**（约 20 秒）。 |
| `~/jt128/app/*.out`（上位机） | ELF **x86-64**，ARM 主机（Jetson / 树莓派等）跑不了。改雷达参数请回 x86 桌面机。 |

移植包只装**源码 + 脚本 + 文档**，因此只有 370 KB。

## 桌面机独有、机器人主机不需要的部分

| 内容 | 依赖 | 机器人上要吗 |
|---|---|---|
| Gazebo 仿真 HIL（`jt128sim` / `jt128hil` / `sim/*`） | Gazebo + GPU；**仿真包已随 cod 仓库编译**（`src/fzsd_vendor/`），不需要外部 `~/fzsd2025` | 不需要（机器人上跑 Gazebo 没意义） |
| 上位机 LidarUtilities | x86-64 | 不需要（拿桌面机改参数） |
| `memwatch.py` / `完整验收清单.md` | 无 | 可选，做台架验收时用得上 |

## 手工移植（不用脚本的话）

```bash
# 1. 拷源码
rsync -a --exclude .git --exclude build --exclude install ~/HesaiLidar_ROS_2.0/ <主机>:~/HesaiLidar_ROS_2.0/
rsync -a ~/hesai_ws/src/jt128_sim_relay/ <主机>:~/hesai_ws/src/jt128_sim_relay/
rsync -a --exclude app --exclude __pycache__ ~/jt128/ <主机>:~/jt128/

# 2. 改绝对路径（在主机上执行，把 $HOME 换成实际路径）
sed -i "s|\"/home/wzj/HesaiLidar_ROS_2.0|\"$HOME/HesaiLidar_ROS_2.0|g" ~/HesaiLidar_ROS_2.0/config/config.yaml
grep -n "file_path\|firetimes_path" ~/HesaiLidar_ROS_2.0/config/config.yaml   # 确认改对了

# 3. 编译
mkdir -p ~/hesai_ws/src && ln -sfn ~/HesaiLidar_ROS_2.0 ~/hesai_ws/src/HesaiLidar_ROS_2.0
cd ~/hesai_ws && source /opt/ros/$ROS_DISTRO/setup.bash && colcon build --symlink-install
```

## 已经在真机上验证过的部分

我在隔离的假 `$HOME`（`/tmp/jt128_fakehome`）里跑了完整流程，结果：

- `deps_check.sh`：16 通过 / 2 警告 / 0 失败
- `port_setup.sh`：改写两处路径成功且文件存在 → 驱动编译 19.3s、中继 5.9s **均成功**
- 编译产物启动正常：`Hesai Lidar ROS V2.0.12 / SDK V2.0.12`，socket 打开、UDP 线程起来

也就是说，只要目标机 ROS 2 + 那几个 dev 包齐了，这套东西落地不需要改代码。
