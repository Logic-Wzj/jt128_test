# JT128 上手步骤（照着敲就行）

> 终端是 zsh，下文命令直接粘贴。`sudo` 需要你自己输密码。
> 建议开 **3 个终端**：A 跑驱动、B 跑验证/占用、C 跑上位机改参数。

---

## 第 0 步（只做一次）：让 Clash 放行雷达网段

**必须先做**，否则 `192.168.1.201` 会被 Clash 的 TUN 劫持（fake-ip `198.18.0.0/15`），
表现是"IP 配了、ping 不通、抓不到包"，驱动还会假装 `ptc connect success`。

做法（任选其一）：
- Clash Verge → 设置 → TUN → 把 `192.168.1.0/24` 加进 `route-exclude-address`（或开启"绕过局域网"）
- 或者测试期间直接关掉 TUN / 退出 Clash

验证（**必须看到 `dev enp131s0`，不能是 `dev Meta`**）：

```bash
ip route get 192.168.1.201
# ✅ 期望：192.168.1.201 dev enp131s0 src 192.168.1.100
# ❌ 若还是：via 198.18.0.2 dev Meta table 2022   → Clash 还在劫持
```

## 第 1 步：接线、上电

- 电源 **9~32 V，≥2.6 A / 30 W**；针脚 `6 红=Power`、`1 黑=GND`；**断电插拔**
- 网线接电脑网口（要拔掉校园网那根；WiFi 记得开着，不然没网）
- 摘下光罩保护棉
- 上电后耳朵能听到转起来；不确定是否出光可用手机摄像头看光斑

## 第 2 步：给电脑配 IP

```bash
sudo ~/jt128/setup_host.sh enp131s0 192.168.1.100
```

脚本会拉起网卡、加 `192.168.1.100/24`、ping 雷达并提示下一步。
ping 不通**不算失败**（部分固件不回 ICMP），看第 3 步。

## 第 3 步：先证明"雷达在发数据"（不依赖 ROS）

```bash
python3 ~/jt128/jt128_check.py --iface enp131s0 --seconds 20
```

期望输出（出厂默认是双回波）：

```
时间       RSS/MB ... 9000 包/s | 82.51 Mbps | 帧率 10.0 Hz | 转速 600.0 RPM | 丢包 0.00%
```

| 工况 | 包/s | 带宽 |
|---|---|---|
| 10 Hz 单回波 | ≈4500 | ≈41 Mbps |
| 10 Hz 双回波（默认） | ≈9000 | ≈82 Mbps |

**这一步过了 = 供电/线缆/IP/出光/电机全部正常**，后面都是软件问题。
没过就按最后面的排查顺序查。

## 第 4 步：加载 zsh 片段（一次）

```bash
source ~/jt128/jt128.zsh
# 想每次自动加载：
echo 'source ~/jt128/jt128.zsh' >> ~/.zshrc
```

加载后可用：`jt128env / jt128up / jt128raw / jt128verify / jt128mem / jt128check / jt128down / jt128status`

## 第 5 步：终端 A —— 起驱动 + 滤波

```bash
jt128up
```

起三个东西：禾赛驱动（→ `/lidar_points`）、`cpp_lidar_filter`（→ `/livox/lidar_filtered`）、`base_link→front_jt128` 静态 TF。
**cod 仓库一行没改**：滤波节点只是把输入话题改成了 `/lidar_points`，输出仍是 nav2 认的 `/livox/lidar_filtered`。

停的时候在这个终端按 **Ctrl+C**（**别用 `timeout ros2 launch`**，会留下孤儿进程）。

## 第 6 步：终端 B —— 验证 + 测占用

```bash
jt128verify                 # 等约 1 分钟，逐项给 ✅/❌
jt128mem --seconds 1800     # 内存/CPU/FD/内核缓冲，跑 30 分钟
```

`jt128verify` 会检查 7 组：进程、话题、频率、点数、frame_id、丢包、TF、资源。
期望：**全部 ✅**，其中点数应为 `115200`（单回波）或 `230400`（双回波）。

内存判据：RSS 增长斜率 **|≤1 MB/min|**、FD 数不变、**RcvbufErrors 增量 = 0**。
基线参考：驱动空跑（无数据）就占 **148 MB**，插上雷达后会涨。

## 第 7 步：终端 C —— 上位机改参数（功能验收）

```bash
~/jt128/app/*.out
```

在界面里逐项切、回终端 B 看数字变化（这就是"功能完好"的硬证据）：

| 操作 | 期望 |
|---|---|
| Spin Rate 600 ↔ 1200 RPM | 帧率 10 ↔ 20 Hz，转速读数同步 |
| Return Mode 单回波 3 种 / 双回波 3 种 | 点数 115200 ↔ 230400、带宽 41 ↔ 82 Mbps |
| Azimuth FOV 设 `[0°,90°]` | 包率降到约 1/4，点云只剩该扇区 |
| Standby Mode 待机 → 切回 | 待机无点云，切回恢复 |
| Reset All Settings | 参数回默认（测完记得复位，或改回你要的值） |

> 建议：第一轮把雷达切成**单回波**跑，带宽/点数减半，先保证链路稳，再谈双回波。

完整勾选项见 `~/jt128/完整验收清单.md`（92 项）。

## 第 8 步：收工

```bash
jt128down                       # 杀掉驱动/滤波/TF，清理残留
sudo ip addr del 192.168.1.100/24 dev enp131s0   # 归还网口给校园网（可选）
```

## 出问题时按这个顺序查

```
点云没数据
 ├─ 1. ip route get 192.168.1.201        → 是 dev Meta？Clash 还在劫持，回第 0 步
 ├─ 2. ip -br addr show enp131s0         → 有没有 192.168.1.100/24？没配成功
 ├─ 3. sudo tcpdump -i enp131s0 -n -c5 udp port 2368   → 有没有 1146 字节包？
 │      ├─ 有 → 物理链路 OK，问题在 ROS/驱动层，看第 4 步
 │      └─ 无 → 供电(9~32V/≥2.6A)、M8 针脚(6红/1黑)、网口收发交叉(4,5=TX / 3,2=RX)
 └─ 4. jt128verify 的报错项
        ├─ 点数既不是 115200 也不是 230400 → 驱动回波模式与雷达不一致
        ├─ frame_id 不对                    → config.yaml 的 ros_frame_id
        └─ TF 不通                          → use_static_tf:=true 或补安装偏移
```

其它速查见 `~/jt128/README.md` 第 7 节（手册第 6 章故障对照）。
