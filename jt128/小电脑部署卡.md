# 小电脑部署卡（i7 / x86-64 / 有图形界面 / 有 cod 工作区）

> 目标：把小电脑变成能测 JT128 的机器（驱动编译好、工具齐全、上位机能开）。
> 全程约 5 分钟，其中编译约 25 秒。

## 0. 先把文件弄过去（桌面机上准备）

### 方式 1：走 GitHub（不用 U 盘，推荐）

```bash
# 桌面机：整理成仓库并推送（详细说明见 GitHub传包.md）
bash ~/jt128/port/push_to_github.sh --dir ~/jt128_repo --with-driver
cd ~/jt128_repo
git remote add origin https://github.com/<你>/jt128-test-kit.git
git push -u origin main

# 小电脑：clone 下来（-b main 防止默认分支不一致 clone 出空目录）
git clone -b main https://github.com/<你>/jt128-test-kit.git jt128_test
cd jt128_test
```

用这种方式**跳过下面第 1 节**（不用解包），直接做第 2 节。
上位机 GUI 那个 97 MB 二进制不要进仓库，单独 scp 或留在桌面机。

### 方式 2：压缩包 scp / U 盘

```bash
# ① 移植包（约 400 KB，必需）
ls -lh ~/jt128_port_*.tar.gz
sha256sum ~/jt128_port_*.tar.gz          # 到小电脑后校验用

# ② 上位机 GUI（97 MB，可选；小电脑有图形界面所以值得拷）
ls -lh "/mnt/d_drive/linux_download/LidarUtilities_Sample_JT128_3.0.5_65677db_ubuntu22.out"

# 拷（二选一）
scp ~/jt128_port_*.tar.gz "/mnt/d_drive/linux_download/LidarUtilities_Sample_JT128_3.0.5_65677db_ubuntu22.out" <小电脑>:~/
# 或 U 盘
```

**不要拷**：`~/hesai_ws`（软链+绝对路径，换机必坏）、`~/HesaiLidar_ROS_2.0`（已在包里）、`~/cod_-rm2026_-navigation`（小电脑上本来就有）。

## 1. 校验 + 解包（仅方式 2 需要）

```bash
cd ~
sha256sum jt128_port_*.tar.gz            # 与桌面机上打印的一致即可
tar xzf jt128_port_*.tar.gz
cd jt128_port_*
```

## 2. 依赖自检（先看缺什么）

```bash
bash jt128/port/deps_check.sh
```

期望：大部分 ✅。**有图形界面的机器通常只差这两个编译依赖**：

```bash
sudo apt install libyaml-cpp-dev libboost-thread-dev
```

如果它提示缺 Qt6 运行库（跑上位机要用）：

```bash
sudo apt install libxcb-cursor0 libxkbcommon-x11-0 libxcb-xinerama0 libgl1 libegl1 libdbus-1-3
```

> `[4] 现有工作区` 那节会显示它找到的 cod 工作区路径。**如果路径不是 `~/cod_-rm2026_-navigation`**，
> 记住它，后面用 `export COD_WS=<实际路径>`。

## 3. 一键部署 + 编译

```bash
bash jt128/port/port_setup.sh "$PWD"
```

它会依次：装工具集到 `~/jt128` → 装驱动源码到 `~/HesaiLidar_ROS_2.0` →
**改写 config.yaml 里的绝对路径** → `colcon build`（驱动+中继）→ 配 shell 入口。

期望结尾看到 `Summary: 2 packages finished`。

## 4. 上位机（可选，有图形界面就能开）

```bash
mkdir -p ~/jt128/app && mv ~/LidarUtilities_Sample_JT128_*.out ~/jt128/app/
chmod +x ~/jt128/app/*.out
~/jt128/app/*.out
```

界面里能连上雷达后，**第一件事把回波模式切成单回波**（后面接机器人更省）。

## 5. 验收

```bash
cd ~/jt128
./launch.sh                 # 总览：ROS 版本 / 各工作区 / 网卡 / 进程
./launch.sh help            # 全部命令
```

接上雷达后的测试流程：

```bash
./launch.sh net             # 配主机 IP（sudo；网卡自动探测）
./launch.sh check           # 裸 UDP 收包：≈9000 包/s、82 Mbps（出厂双回波）
./launch.sh driver          # 只起禾赛驱动
./launch.sh verify          # 点云逐项检查（频率/点数/frame_id/丢包）
./launch.sh mem             # 内存/CPU/FD/内核缓冲
```

## 6. 出问题先看这三条

| 现象 | 先查 |
|---|---|
| `check` 没数据 | `./launch.sh` 看"到雷达路由"是否被 Clash 劫持；`ip -br addr` 看有没有 192.168.1.x；`sudo tcpdump -i <网卡> -n -c5 udp port 2368` |
| `driver` 起不来 | `./launch.sh fixpaths`（路径）；缺 `libyaml-cpp-dev` / `libboost-thread-dev`（编译期就该报过）；`ROS_DISTRO` 是否对 |
| 找不到 cod 工作区 | `export COD_WS=<实际路径>`（只在用仿真/接管导航时才需要，今天测雷达用不到） |

## 备注

- 小电脑上有 cod 工作区，意味着**将来也能在这台机器上跑仿真 HIL**（`./launch.sh sim` + `./launch.sh hil`），
  但那要 Gazebo + GPU，今天不用。
- 目录可以随便改名（比如 `jt128_test`），脚本是自定位的；改完 `./launch.sh fixpaths` 一次即可。
