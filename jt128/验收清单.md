# JT128 精简验收清单（只要：内存占用 + 功能完好）

## A. 内存 / 资源占用（主机侧实测）

> 雷达板子内部的"内存占用"厂家没有对外读取接口（手册第 4 章：这些参数用户无法读写），
> 只能通过 PTC `Get Lidar Status (0x09)` / LidarUtilities 看运行状态和温度。
> 真正能测的是**点云链路在主机上的开销**，分三块，别混在一起看。

| 观测项 | 怎么测 | 健康标准 |
|---|---|---|
| 接收进程内存/CPU | `python3 ~/jt128/memwatch.py --list` 找进程 → `--name LidarUtilities` 或 `--pid <驱动节点PID> --seconds 1800` | RSS 增长斜率 \|<\|=1 MB/min、FD 数不变、CPU 平稳 |
| 内核 UDP 收包缓冲 | 同上，脚本自带 Recv-Q 和 RcvbufErrors | Recv-Q 峰值不持续堆积、**RcvbufErrors 增量 = 0** |
| 带宽/包率（开销的根源） | `python3 ~/jt128/jt128_check.py --seconds 60` | 单回波 ≈41 Mbps / 双回波 ≈82 Mbps；丢包 0% |

量级参考（实测后自己填）：

| 程序 | 预期 RSS | 备注 |
|---|---|---|
| `jt128_check.py` | 15~25 MB | 纯 Python 收包+解析的"地板" |
| ROS 2 Hesai 驱动节点 | 几十 MB | 双回波 CPU 约为单回波 2 倍 |
| LidarUtilities | 数百 MB | PySide6+OpenGL GUI，**别用它判断"雷达吃多少内存"**，它自己就是个大程序 |

关键判据：**把回波模式从双回波切到单回波，CPU 和带宽应大致减半** —— 这同时也是"参数确实写进雷达了"的旁证。

## B. 功能逐项验收表

| # | 功能 | 怎么测 | 期望 |
|---|---|---|---|
| 1 | 电机转动 / 上电 | 上电听声音看旋转；`sudo tcpdump -i enp131s0 -n -c 5 udp port 2368` | 旋转平稳、有 1146 字节包 |
| 2 | 点云数据输出 ★ | `jt128_check.py --seconds 60` | 10 Hz 单回波 ≈4500 包/s；双回波 ≈9000；帧率≈转速/60；丢包 0% |
| 3 | 帧率 10 / 20 Hz（600 / 1200 RPM）★ | LidarUtilities 切 Spin Rate，同时看 `jt128_check` 打印的帧率与转速 | 10.0±0.2 Hz / 20.0±0.4 Hz；数据尾 Motor Speed 同步变化 |
| 4 | 回波模式（6 种）★ | 逐个切换：单回波 第一/最强/最后；双回波 最后&最强（默认）/最后&第一/第一&最强 | 数据尾 Return Num 1↔2、Return Mode 码值对应；包率/带宽成比例变化 |
| 5 | Azimuth FOV ★ | 设 `[0°, 90°]`、`[270°, 90°]` 等 | 包率按角度占比下降；PandarView/LidarUtilities 里点云只剩该扇区 |
| 6 | 待机 / 运行 ★ | 切 Standby，再切回 Run | 待机无点云输出；切回后恢复；数据尾 Working Mode 0/1 对应 |
| 7 | 网络参数可写 | 改目的端口或源 IP（主机侧记得同步） | 改完立即生效；**测完改回 192.168.1.201 / 2368** |
| 8 | 雷达信息 / 固件版本 | LidarUtilities 信息页 | 型号 JT128、序列号、固件版本正常显示 |
| 9 | 内部状态 / 温度 ★ | 数据尾 IMU 温度；PTC 0x09 | 连续跑 30 min 温度稳定，不断流不降频 |
| 10 | IMU | 手动晃动雷达 | 数据尾加速度/角速度数值跟着变 |
| 11 | 时间戳 / 绝对时间 | 看数据尾 Date & Time + 微秒 | 无 GNSS/PTP 时是内部时钟（会漂），接 GNSS/PTP 后才与真实时间对齐 |
| 12 | 视场完整性 / 光罩 | 看整圈点云 | 无缺扇区；Confidence 高位（视窗脏污等级）应低 |
| 13 | 固件升级 | **不建议主动测** | 有变砖风险，除非厂家要求；升级时保证供电稳定 |

★ = 必测，最容易暴露问题。1/7/11/12 顺手看一眼，13 跳过。

## 跑的顺序（约 30 分钟）

```bash
# 1) 配 IP（只需一次）
cd ~/jt128 && sudo ./setup_host.sh enp131s0 192.168.1.100

# 2) 终端 A：先确认数据正常，记下包率/带宽
python3 ~/jt128/jt128_check.py --iface enp131s0

# 3) 终端 B：起上位机，逐项切参数（第 3~9 项）
mkdir -p ~/jt128/app && cp /mnt/d_drive/linux_download/LidarUtilities_Sample_JT128_3.0.5_65677db_ubuntu22.out ~/jt128/app/ \
  && chmod +x ~/jt128/app/*.out && ~/jt128/app/*.out

# 4) 终端 C：盯内存/CPU/内核缓冲（第 A 节）
python3 ~/jt128/memwatch.py --list
python3 ~/jt128/memwatch.py --name LidarUtilities --seconds 1800
```

每切一次参数，回终端 A 看包率/带宽是否按预期变化，这就是"功能完好"最硬的证据。
