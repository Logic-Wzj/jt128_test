# 接上雷达后怎么用（照着走）

> 终端是 zsh。先 `source ~/jt128/jt128.zsh`，下面的 `jt128*` 命令才可用。
>
> **小电脑上没有 zsh / 不想配环境？用 bash 版入口 `~/jt128/launch.sh`**（纯 bash、不依赖 zsh、
> 不写死任何路径与网卡名，可整目录拷到别的机器）：
> ```bash
> ./launch.sh              # 环境/网络/进程 总览
> ./launch.sh help         # 全部命令
> ./launch.sh net          # 配主机 IP（sudo）
> ./launch.sh check        # 裸 UDP 收包
> ./launch.sh driver       # 只起禾赛驱动
> ./launch.sh verify       # 点云逐项检查
> ./launch.sh fixpaths     # 换机后修复 config.yaml 里的绝对路径
> ```

## 接之前先做两件事（不做后面全是假故障）

**① 先确认雷达 IP 没被 Clash 劫持**（不用无脑放行）

你机器现在 Clash 的 **TUN 是关闭的**（`tun.enable: false`，GUI 也不自启），此刻没有任何劫持。
只有当你**打开 TUN 模式**时，`192.168.1.201` 才会被 fake-ip 劫持。判断方法：

```bash
jt128route        # 一键检查（见下）
# 或手动：
ip route get 192.168.1.201
# ✅ 没被劫持：via 10.132.255.254 dev enp131s0   ← 走校园网默认路由
#            或配好 IP 后：dev enp131s0 src 192.168.1.100
# ❌ 被劫持：  via 198.18.0.2 dev Meta table 2022
```

被劫持了才需要放行，而且要放对地方（否则重启就丢）：

| 写在哪 | 重启后还在吗 |
|---|---|
| Clash Verge → **全局扩展配置（Merge）** 里的 `tun.route-exclude-address`，或 GUI 的 TUN 设置 | ✅ 持久（换订阅也保留） |
| 直接改 `~/.local/share/io.github.clash-verge-rev.clash-verge-rev/clash-verge.yaml` | ❌ **不持久**，Verge 每次生成配置会覆盖（目录里有 `*.bak-regen-*` 备份就是证据） |
| 临时 `ip rule add ...` 绕过 | ❌ 不持久，而且 TUN 关掉后残留规则会造成**黑洞**（包被送进已失效的 table 2022） |

**② 接线**：电源 9~32 V / ≥2.6 A，**断电插拔**，摘掉光罩保护棉，拔掉校园网那根线插雷达线。

> 主机 IP 也要注意持久性：`setup_host.sh` / `ip addr add` 加的 `192.168.1.100/24` **重启就没了**，
> 拔插网线时 NetworkManager 也可能清掉。要长期用就建一个 nmcli 连接（见文末）。

## 第 1 步：证明雷达活着（跟软件无关，必过）

```bash
sudo ~/jt128/setup_host.sh enp131s0 192.168.1.100   # 配 IP + ping
jt128check                                           # 裸 UDP 收包统计
```

期望（出厂默认是双回波）：

```
≈9000 包/s | 82 Mbps | 帧率 10.0 Hz | 转速 600 RPM | 丢包 0%
```

| 工况 | 包/s | 带宽 |
|---|---|---|
| 10 Hz 单回波 | ≈4500 | ≈41 Mbps |
| 10 Hz 双回波（默认） | ≈9000 | ≈82 Mbps |

**这一步不过就别往下走**：查 Clash（第 0 条）→ 主机 IP → `sudo tcpdump -i enp131s0 -n -c5 udp port 2368` → 供电/针脚。

## 第 2 步：选一条路

### 路线 A：接真机导航栈（台架/真车上跑）

```bash
jt128up          # 起：驱动 + cpp_lidar_filter + base_link->front_jt128
jt128verify      # 另开终端，逐项验收（默认 MODE=real）
jt128mem --seconds 1800     # 内存/CPU/FD/内核缓冲
```

数据流：`/lidar_points` → `cpp_lidar_filter` → `/livox/lidar_filtered`（nav2 原本就在听这个话题）。
**cod 仓库一行没改**：滤波节点只是把输入话题参数改成了 `/lidar_points`。

### 路线 B：接 Gazebo 仿真（HIL，不用整车）

```bash
# 终端 1：仿真（障碍源已换成点云）
jt128sim

# 终端 2：等仿真起来（1~2 分钟）后
jt128hil

# 终端 3：验证
MODE=sim bash ~/jt128/jt128_verify.sh
```

数据流：`/lidar_points` → `jt128_sim_relay`(C++) → `/jt128/points` → 仿真 local_costmap。

⚠️ 仿真这一侧必须带 Fast DDS profile（`jt128.zsh` 已自动 export；手动开终端的话：

```bash
export FASTRTPS_DEFAULT_PROFILES_FILE=$HOME/jt128/sim/fastdds_large_msg.xml
```

不设的话 1.84 MB/帧的点云会在 DDS 层被丢掉，现象是"发布端 10 Hz、costmap 端只有 1~2 Hz"）。

**没接雷达也想先跑通仿真链路**：`jt128hil source:=fake`，用合成点云（四面墙 + 正前方柱子）。

## 第 3 步：调参数（上位机）

```bash
~/jt128/app/*.out        # LidarUtilities
```

**第一件事：把回波模式切成单回波**（`第一/最强/最后` 任一个）。
理由：双回波是 230400 点/帧 ≈ 3.7 MB/帧，带宽 82 Mbps，对 DDS、costmap、nav2 都是压力；切单回波后点数/带宽直接减半，先把链路跑稳再谈双回波。

其它可调：Spin Rate（600↔1200 RPM）、Azimuth FOV（只输出前方扇区，省算力）、Standby。
切完回终端看 `jt128check` / `jt128verify` 的数字是否按预期变——这就是"功能完好"的硬证据。
测完记得把参数改回比赛要用的值（`Reset All Settings` 会清掉所有设置）。

## 收工

```bash
jt128down                                        # 杀掉驱动/中继/滤波/TF（别用 timeout，会留孤儿进程）
sudo ip addr del 192.168.1.100/24 dev enp131s0   # 网口还给校园网（用 nmcli 建的连接则 nmcli con down jt128）
```

## 重启之后要重新做什么

| 项目 | 重启后 |
|---|---|
| Clash 的 TUN / 系统代理 | **不会自动开**（`enable_auto_launch: false`、`enable_tun_mode: false`），只有 `clash-verge-service` 后台服务自启 → 默认无劫持，**不用管放行** |
| 主机 IP `192.168.1.100/24`（`ip addr add` 方式） | **丢**，要重新 `sudo ~/jt128/setup_host.sh ...` |
| 主机 IP（nmcli 方式，见下） | 自动恢复 ✅ |
| `FASTRTPS_DEFAULT_PROFILES_FILE` | 只要 `.zshrc` 里有 `source ~/jt128/jt128.zsh` 就自动恢复 ✅ |
| 雷达驱动/仿真 | 都要重新启动（本来就不是常驻服务） |

**持久化网口配置（推荐，一次搞定）**：

```bash
sudo nmcli con add type ethernet ifname enp131s0 con-name jt128 ip4 192.168.1.100/24
sudo nmcli con up jt128          # 插上雷达线即用，重启自动生效
sudo nmcli con down jt128        # 测完切回来；切校园网用原连接 nmcli con up <名字>
```

**重启后 30 秒自检**：

```bash
jt128route                       # 1. 有没有被 Clash 劫持
ip -br addr show enp131s0        # 2. 有没有 192.168.1.100/24
jt128check                       # 3. 雷达在不在发数据
```

## 三个容易踩的坑

1. **不要用 `timeout ros2 launch ...`** —— timeout 只杀 launch 父进程，节点会被 init 收养变孤儿一直跑（我踩过，两个僵尸各占 152 MB）。停就 Ctrl+C，或 `jt128down`。
2. **测性能前先安静** —— Gazebo、RViz、`update-manager` 都会抢 CPU（实测 update-manager 单核 98%），这种状态测出的内存/CPU 没参考价值。
3. **回波模式两边必须一致** —— 雷达是双回波而驱动按单回波解析（或反之），点云数量和时间戳都会错乱。

## 参考基线（空跑实测，供对照）

| 进程 | RSS |
|---|---|
| hesai_ros_driver（无数据空跑） | ≈148 MB |
| jt128_sim_relay（满速 115200 点/帧） | ≈95 MB |
| cpp_lidar_filter | ≈33 MB |

插上雷达跑起来后，驱动 RSS 会明显高于空跑值 —— 那正是你要观测的"内存占用"。判据：增长斜率 \|≤1 MB/min\|、FD 数不变、内核 `RcvbufErrors` 增量 0。
